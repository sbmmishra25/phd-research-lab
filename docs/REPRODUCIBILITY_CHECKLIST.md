# Reproducibility Checklist

Before treating an experiment as a research result:

- [ ] Research question and hypothesis are explicit.
- [ ] Dataset version/source is recorded.
- [ ] Train/validation/test split is leakage-safe.
- [ ] Preprocessing is fitted only on training data.
- [ ] At least one meaningful baseline is implemented.
- [ ] Random seeds are recorded.
- [ ] Dependency versions are pinned or documented.
- [ ] Hardware/simulator/backend details are recorded.
- [ ] Hyperparameters are stored in a configuration or command.
- [ ] Primary and secondary metrics are defined before comparison.
- [ ] Resource cost is measured where relevant.
- [ ] Ablation experiments are defined.
- [ ] Multiple seeds are used for stochastic claims.
- [ ] Results are generated by executable code, not manually invented.
- [ ] Failure cases and limitations are documented.
- [ ] The exact repository commit is recorded with the result.
- [ ] No credentials, API keys, private datasets, or personal data are committed.
